00:00 I built SMP Intelligence to make automotive catalog lookups easier to explore without writing SQL.

00:05 Here is the working Windows prototype. I ask which parts cross to an original-equipment reference.

00:14 SQL Server returns matching parts, which the application presents in the conversation and results table.

00:20 A follow-up retrieves their vehicle applications. Part numbers, usernames, and regional vehicle counts are blurred in this walkthrough.

00:28 The SQL tab exposes the query proposed by the model. The backend checks and normalizes that proposal before executing it.

00:37 OpenAI proposes the query. SQL Server supplies the result records, which are formatted locally and are not sent back to the model.

00:45 The public validator is adapted from the prototype. It parses SQL into a syntax tree and requires one SELECT statement per result.

00:54 Table references, syntax, and functions have explicit limits. Unsupported operations are rejected rather than passed through.

01:04 Execution order matters. The pipeline materializes the entire validated plan before the first database call.

01:14 If a second query is rejected, the first query must not run either. The sample preserves this behavior from the original prototype.

01:23 This public test supplies a rejected second query and checks that the executor was called zero times.

01:33 All 105 public cases passed in this run. These tests check defined behaviors; model-generated answers still need separate business-correctness evaluation.

01:41 The original uses OpenAI, SQL Server, and WPF. The public sample uses an offline planner and fictional SQLite data so reviewers can run and inspect it without company access.

01:53 Explore the source, run the tests, or try the browser demo. SMP Intelligence remains a working prototype.
